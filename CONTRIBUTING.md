# Contributing to SovImage

Thanks for your interest. SovImage is a small project; we keep the bar
high and the loop short.

## Quick start

See [BUILDING.md](BUILDING.md) for full toolchain setup. TL;DR:

```bash
git clone https://github.com/asifwanders/SovImage.git
cd SovImage
git submodule update --init --recursive
cd frontend
npm install
npm run dev       # browser-only, mock IPC
```

## How we work

### Issues

- Search before filing — duplicates get closed.
- Bug reports: include OS/arch, sd.cpp commit (`git -C vendor/stable-diffusion.cpp rev-parse HEAD`),
  app version, and steps to reproduce.
- Feature requests: explain the user problem first, the proposed solution
  second.

### Pull requests

- One concern per PR. A 200-line PR doing one thing beats a 2000-line PR
  doing five.
- Branch from `main`. Rebase before merging; we don't squash-merge.
- Add or update tests when touching Rust modules under `src-tauri/src/`.
- Run before pushing:
  ```bash
  cd frontend
  npx tsc --noEmit
  npm run build
  cd src-tauri
  cargo test --lib --no-default-features
  cargo check --no-default-features
  ```
- Keep the PR description plain technical prose. No emoji-laden conventional
  prefixes, no co-author trailers added by tooling. Title format:
  `<area>: <imperative phrase>` (e.g. `downloader: handle 416 on partial restart`).

### Commits

- Imperative mood: "fix race in setup runtime", not "fixed" or "fixes".
- First line ≤ 72 chars. Body explains *why*, not *what*.
- No co-author trailers. No "generated by …" lines. Write commits the way
  any other engineer would.

## Code style

### Rust

- Edition 2021. `cargo fmt` before pushing (project uses default rustfmt).
- Async via `tokio`. Avoid `tokio::sync::Mutex` for trivially-readable
  state; prefer `std::sync::Mutex` if no `.await` is held.
- Errors via `thiserror` enum + `?`. Never `unwrap()` outside tests.
- Public API in modules gets a `///` doc comment explaining intent, not
  mechanics.

### TypeScript / React

- TypeScript strict mode. No `any` without a comment justifying it.
- Functional components only. Hooks only at top level.
- Zustand stores: **per-field selectors** (`useStore((s) => s.field)`),
  never `const { a, b } = useStore()`.
- Tailwind utility classes; named CSS classes only for cross-cutting
  utilities in `globals.css` (e.g. `.glass-panel`).
- Use `cn()` from `lib/utils.ts` for conditional classes.

### Plans

Anything touching > 3 files gets a numbered doc in `plan/` first. Look at
`plan/01-frontend-layout.md` for the format.

## Architecture pointers

| Concern              | Lives in                                              |
|----------------------|-------------------------------------------------------|
| UI                   | `frontend/src/components/`                            |
| State                | `frontend/src/lib/stores/` (Zustand)                  |
| DB                   | `frontend/src/lib/db.ts` (plugin-sql driver)          |
| IPC                  | `frontend/src/lib/ipc.ts` (narrow Tauri surface)      |
| Setup runtime        | `frontend/src-tauri/src/commands/setup.rs`            |
| Downloader           | `frontend/src-tauri/src/downloader/`                  |
| Hardware probe       | `frontend/src-tauri/src/hardware/`                    |
| sd.cpp supervisor    | `frontend/src-tauri/src/sidecar/`                     |
| Migrations           | `frontend/src-tauri/migrations/`                      |
| CI                   | `.github/workflows/`                                  |

## Releases

Maintainers tag `vX.Y.Z` on `main`. CI builds installers for macOS arm64
and Windows x64, opens a draft GitHub Release with the artifacts attached.
A maintainer reviews + publishes.
